# Every line here carries a `>=` floor, and that is the point of the file.
#
# A bare requirement name is satisfied by whatever version happens to already
# be installed, so `pip install -r requirements.txt` against an existing tree -
# which is exactly what `deploy/update.py` runs on the other installs of this
# portal, and what `deploy/setup.py` runs on a rebuilt venv - leaves an old
# version exactly where it is and exits 0. Nothing about that reads as a
# failure anywhere. A floor turns the same command into an upgrade, which is
# how a fix reaches every OTHER install instead of the one machine somebody
# typed on.
#
# Site-wide tools' install-watch graded this file on 2026-09-21 and found nine
# of the ten lines unbounded - the only such file on the estate, because every
# other python environment here either installs into a fresh image or is
# pinned with `==`. The floors below are the versions this portal is running
# and its suite is green on, so they are a statement about what is proven
# rather than a guess. `tests/test_requirements_floors.py` enforces every one
# of them against the interpreter running the suite, and fails a commit that
# declares a floor this venv does not meet.
#
# Raising a floor is the whole remedy for the next advisory: change the number
# here, and the install on every box follows on its next update.
